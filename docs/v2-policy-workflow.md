## 固定执行顺序

1. **确认范围。** 接受 ISO 日历日期和可选地区。开始日包含，结束日不包含。缺日期或顺序颠倒时提示补充。
2. **加载政策。** 从仓库内的 Markdown 读取结构化生效日期和退款上限，同一文档保留供人核对的原文。政策生效以订单下单日期为准。
3. **切分日期。** 将请求区间与各政策版本的生效区间相交，检查结果能完整、无重叠覆盖请求。发现缺口或冲突时先停止。
4. **查询订单。** 每段使用固定 SQL 模板和绑定参数，经 SQLite 只读连接与 `EXPLAIN` 校验执行。金额以整数分计算，逐订单应用上限。政策问数使用独立种子库，只访问 `orders`。
5. **核对与汇总。** 规则核对生效范围、SQL 参数与返回字段、证据引用、分段金额和退款上限。失败时返回原因并隐藏未通过核对的数字。成功时返回合计、分段、政策原文及查询证据。

首版的 Verifier 使用结构化政策和 SQL 证据执行规则。它依赖随代码审核的元数据，未对任意政策自然语言与元数据的语义一致性做自动判定。首版支持一个指标与一个演示数据源。后续对照可以复用政策、查询与核验逻辑，比较同数据上的编排结果。

## 验收与复现

```bash
curl -fsS http://127.0.0.1:28000/api/v2/policy-revenue \
  -H 'Content-Type: application/json' \
  --data '{"start":"2026-10-01","end_exclusive":"2026-11-01","region":"华南"}'
```

返回 `kind=answer`、`total_cents=17700`、两个分段以及政策和 SQL 证据。还可查看每步状态、执行用时、SQL 次数与模型次数。

用项目 Python 环境运行验收题。第一条创建临时 SQLite，第二条通过正在运行的 API 复测。题集包含 8 个答案、4 个澄清和 3 个拒答案例，逐段核对时间、政策版本、地区、金额、订单数、绑定参数及证据。
