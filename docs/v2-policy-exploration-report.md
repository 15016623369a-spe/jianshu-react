# 见数 V2 · 政策探索与计划缓存验收

2026 年 11 月 15 日。按 Plan-and-Execute 测评报告优先完成难例、文档检索、按证据选账本和已核验计划缓存。普通「政策问数」继续默认走固定流程。新增「政策探索实验」默认按确定性流程、计划缓存与必要时的模型规划执行，支持固定检索、缓存优先和实时规划对照。

## 测评项和实现

- **无 ID 引用、自然语言标题和公告版本。** 从 Markdown 索引检索候选，再核对正文中的「最新公告」或《标题》与元数据是否一致。使用正式来源、产品或类目、地区及完整生效区间过滤。最新公告取覆盖请求区间的候选，同等适用就拒答。
- **类目政策和相似文档。** 目录先解析产品类目，专属产品政策优先于类目。说明性 FAQ 可以命中检索，但不能授权扣减。缺正式政策、缺公告或版本冲突时均停止汇总。
- **按证据查表。** 公告决定用 `orders`、`refunds` 或 `chargebacks`。外部账本先核对实际表与字段，再生成白名单内的参数化只读 SQL。先合并同一订单的台账记录，再按单笔上限计算。核验器检查账本、参数和金额。金额使用整数分。
- **缓存与重规划。** 缓存存储通过核验的工具序列，按任务版本和基础政策标识、地区、生效范围及引用方式等区分。每次重新读取政策、公告和账本并执行查询。缓存进程内有界，重启后重新积累。缺步骤或计划依赖不符时最多重规划一次，保留已经查到的证据。权威来源缺失、相互冲突、账本字段不符合和预算耗尽均停止。

模型输出约束在工具序列。文档检索属于受控 Markdown 语料，应用根据已验证账本生成 SQL。此轮不引入模型任意 SQL、开放文档问答或 DAG 并行。当前公告、账本和 SQL 探查之间有证据依赖。

## 三组实测

25 道冻结留出题各跑三轮。同一个 DeepSeek V4 Pro、温度 0，共享同一套数据、检索、查询与核验规则。缓存优先组每轮用 4 道不同开发题预热，与留出题分开。固定和实时规划最多 5 个工作线程，缓存组顺序处理以避免并发首次写入改变命中统计。延迟从调用应用开始计时，包含模型等待、排除评测排队和预热。

| 指标 | 固定流程 + 检索 | 实时规划 | 缓存优先 |
| --- | ---: | ---: | ---: |
| 总通过 | 75/75 | 75/75 | 75/75 |
| 金额与证据、工具路径正确 | 48/48 | 48/48 | 48/48 |
| SQL 汇总次数 | 48 | 48 | 48 |
| P95 | 17.35 ms | 1.10 s | 0.95 s |
| 留出阶段模型调用 | 0 | 57 | 9 |
| 留出阶段 token | 0 | 16,591 | 2,637 |
| 重规划 | 0 | 0 | 0 |

每组另正确处理 21 次拒答和 6 次澄清。缓存优先在 57 次走到规划决策的请求中命中 **48 次**。预热另用了 **12 次模型调用、3,480 token**。计入预热，缓存组共 **21 次调用、6,117 token**，相比实时规划少 **63.2% 调用、63.1% token**。

实时规划生成 **3 种有效工具序列**。按日期找最新公告 24 次，按标题找公告 21 次，直接查账 12 次。执行时有 **4 种实际工具路径**，因为部分按标题找公告的请求最终使用原订单账本，可跳过外部账本探查。48 次金额题覆盖 `orders` 18 次、`refunds` 15 次和 `chargebacks` 15 次。固定检索同样答对，因此未测到规划的准确率增益。

## 关键验收样例

- **同一缓存计划切换账本。** 华南电水壶在 2026 年 10 月匹配售后退款公告，得到 **¥292.80**。11 月再次请求，命中同一计划，重新选中争议扣回公告与 `chargebacks`，得到 **¥246.40**，该次模型调用为 0。
- **按标题和生效期联合解析。** 华北帐篷引用「北区户外售后补扣细则」。10 月选择当时生效的同名版本，走退款台账，得到 **¥1,442.00**。
- **故障注入重规划。** 初始计划只查最新公告，实际 DeepSeek V4 Pro 补出账本探查和查询。已找到的 11 月公告未重复检索，执行一次汇总 SQL 得 **¥246.40**。独立记录该次重规划，未并入留出成绩。[重规划轨迹](../evaluation/baselines/hard_policy_replan_probe_20261115.json)
